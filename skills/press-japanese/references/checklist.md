# 手動チェックリスト（スクリプト不可環境向け）

`uv` が使えず `scripts/factcheck.py` と `lint.py` を実行できない環境（Claude.ai、Cursor のチャット等）では、このリストを目視で当てる。順番は機械検査と同じで、忠実性 → 文体 → AI臭 → 記者視点。忠実性の突合は面倒だが省略しない。ここを省くと、このスキルは文章が上手なだけの捏造機になる。

## 1. 忠実性（factcheck.py の代替）

原稿を先頭から読み、次の要素に印を付けて、一つずつ事実表（なければソース）と突き合わせる。

1. **数値**（金額・人数・割合・日数・件数）。事実表に同じ値があるか。単位・期間・母数・「約」「以上」「税込」が落ちていないか。換算しているなら元の値が復元できるか
2. **日付**（発表日・開始日・発売日・解禁日）。事実表と一致するか。「本日」は発信日が確定しているときだけ
3. **固有名詞**（社名・製品名・人名・肩書・地名・機関名）。正式表記か。ソースにない社名・製品名・人名が混じっていないか。カタカナ語（「クラウド」「AI」）はソースがその語を使っているか
4. **「」内の引用**。ソースと一字一句同じか。違うなら「」を外して伝聞に
5. **最上級・「初」**（世界初・業界初・最大・No.1・唯一）。ソースに根拠（調査名・時期・対象）があるか。なければ削る
6. **推定の語**（見込み・予定・期待される・可能性）。ソースに同じ推定があるか
7. **背景・理由・効果の記述**。ソースのどの行に対応するか指させるか。指せないなら追加か創作
8. **コメント枠**。ソースに発言があるか。なければ枠ごと消して依頼が必要と伝える

一つでも指せない要素が残ったら、削るか【要確認: …】に置き換える。推測で埋めない。

## 2. 文体（press-style.md の要約）

1. リードだけで記者が記事を書けるか（誰が・いつ・何を・いくらで・誰に）
2. 一文は40〜60字前後で、一文一義か。主語と述語が対応しているか
3. 数字は算用数字、1万以上は万・億、日付は西暦、全角数字なし
4. 初出は正式名称、略称は「以下、〇〇」で宣言、人名は肩書つき、自社役員に敬称なし
5. 敬体（発表文・お知らせ）と常体（記事）が混ざっていないか
6. 敬語は一段か（「につきまして」「させていただきます」の重なりがないか）
7. 一人称は「当社」（記事なら「同社」か社名）
8. 地の文に評価語（画期的・革新的・シームレス）がないか。評価はコメント枠にあるか
9. 会社概要・問い合わせ先がそろっているか（記事なら社名の説明が本文にあるか）
10. 見出しの書式が全部同じになっていないか

## 3. AI臭（ai-smell-in-press.md の要約）

1. 「昨今」「近年」「〜が求められる中」の一般論で始まっていないか
2. 「実現」「貢献」「推進」「強化」が本文で各1回を超えていないか。1文に抽象動詞が2つ以上ないか
3. 特長が「3つ」に丸められていないか
4. 本文が箇条書きだけで、経緯と理由が地の文にないか
5. 「今後も〜に貢献してまいります」だけの結びになっていないか
6. 全段落が同じ文数、全見出しが同じ書式になっていないか
7. 記事の締めが「注目される」「期待が高まる」「〜と言えるだろう」になっていないか
8. `natural-japanese/references/manual-checklist.md` の10項目（禁止語・翻訳調・対比の反復・リズム・語彙の使い回し・英語統語）

## 4. 記者視点（最終パス）

初見の記者になったつもりで、次の5問に原稿だけで答えられるかを確かめる。

1. これは何のニュースか（一文で）
2. いつからか、いくらか、誰向けか
3. 何が今までと違うのか（数値で）
4. この主張は誰のものか（帰属が分かるか）
5. 裏取りの電話をどこにかければよいか

答えられない問いがあれば、それは文章の問題ではなくソースの穴。【要確認】として納品時に一覧で渡す。

## 判断台帳と収束

見つけた箇所ごとに「直した／ソースへ戻した／要確認に変更／残す（理由）」をメモしながら進める。理由なしの「残す」はしない。すべての箇所が仕分けられ、直した箇所が新しい問題を生んでいない状態になったら終わり。最後に声に出して通読し、発表文として当たり前に読めるかを確かめる。
